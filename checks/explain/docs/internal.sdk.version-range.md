## Why this matters

This is an internal `otel-checker` error, not a problem with your
project. The cross-language supported-libraries check (used by the JS,
Python, .NET, and Go language checkers) reads a per-language YAML file
that lists every library the OpenTelemetry instrumentation registry
covers, along with the version ranges each instrumentation targets.
This error fires when one of those range strings can't be parsed —
missing bracket, non-semver endpoint, extra commas.

The affected library will simply be missing from the supported-libraries
report for that language. The rest of the checks still run.

For JavaScript and Go, the YAML file is embedded in the `otel-checker`
binary and regenerated by `mise run generate`; a parse failure usually
means either the generation script produced malformed output or the
grammar in the upstream catalog changed. For languages that fetch their
catalog live (Java, Python) the failure typically means an upstream
format change.

## How to fix

You don't need to fix anything in your project; this is a signal to file
a bug so `otel-checker` can handle the new format.

1. Note the module name and version range quoted in the "Internal Error"
   message.
2. Upgrade to the latest release in case the range grammar has already
   been extended:

   ```bash
   go install github.com/grafana/otel-checker/cmd/otel-checker@latest
   ```

3. If the error persists, open an issue on
   [grafana/otel-checker](https://github.com/grafana/otel-checker/issues)
   with the language, the module name, the raw range string, and the
   checker version.
4. For maintainers running against a locally-generated catalog:
   regenerate and check the resulting YAML for shape drift:

   ```bash
   mise run generate
   grep -B1 -A2 "<offending range>" checks/sdk/js/supported-libraries.yaml
   ```

## Example

The parser accepts:

```text
5.0.0                # single version — matches exactly
[5.0.0,)             # 5.0.0 and up
[1.0.0,4.0.0)        # 1.0.0 up to (but not including) 4.0.0
(1.0.0,4.0.0]        # exclusive on the lower end, inclusive on the upper
```

Anything else triggers this error.
